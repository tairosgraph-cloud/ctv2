# Cierre de trabajo - 2026-09-22

**Proyecto:** Tairos.rc v2  
**Fecha de cierre:** 2026-09-22  
**Estado:** avance parcial; permisos por rol reflejados en la interfaz y código verificado en local. Falta validar el comportamiento con cuentas reales en Supabase.

## Objetivo

Continuar el cierre de permisos de usuario para que la interfaz respete los
roles definidos en la migración `0009_cuentas_autorizadas.sql`: gerente,
cajero y contador. El objetivo de este avance fue no mostrar acciones que el
rol no puede ejecutar, sin reemplazar la seguridad que debe aplicar Postgres.

## Trabajo realizado por el agente hoy

- Se creó `src/hooks/usePermisos.ts`.
- El hook consulta una sola vez por sesión la función RPC `mi_rol` y expone:
  - `esGerente`: puede corregir, anular, borrar, cerrar caja y modificar el
    catálogo.
  - `puedeRegistrar`: puede registrar operaciones, cobrar y mover trabajos.
- Se ajustó el catálogo para que solo el gerente vea las acciones de crear,
  editar y borrar productos.
- Se ajustó Clientes para que la creación de clientes o proveedores solo esté
  disponible para cuentas con permiso de registro.
- Se ajustó Deudas para ocultar el botón de abono al contador y la edición al
  usuario que no sea gerente.
- Se ajustó Proformas para que el contador solo consulte; editar y anular
  quedan reservados al gerente, mientras que las acciones de registro quedan
  limitadas a los roles correspondientes.
- Se ajustó Registro para limitar la creación de órdenes, abonos, edición y
  anulación según el rol.
- Se mantuvo el comportamiento permisivo mientras el rol todavía no se conoce
  o cuando la aplicación funciona en modo local; la autoridad final sigue
  siendo RLS y las funciones de Postgres.
