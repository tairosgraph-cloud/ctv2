## Objetivo

Consolidar la migración del prototipo HTML a una aplicación React + TypeScript +
Supabase para gestionar registro contable, órdenes de trabajo, proformas,
deudas, abonos, arqueo de caja, exportaciones y dictado por voz.

## Trabajo implementado

- Migración del prototipo de un solo archivo a una aplicación React con Vite,
  TypeScript y Tailwind.
- Adaptador único de datos con dos modos: Supabase para persistencia real y
  `localStorage` para desarrollo o demostración sin credenciales.
- Migraciones de base de datos para transacciones, órdenes, trabajos,
  proformas, deudas, abonos y cierres de caja.
- Funciones transaccionales para registrar y editar órdenes, actualizar
  proformas y deudas, anular proformas y deshacer abonos sin dejar datos a
  medias.
- Cierre de políticas anónimas de Supabase y preparación de autenticación y
  roles. El soporte completo por usuario todavía no está terminado.
- Registro de órdenes con múltiples trabajos, adelantos, ventas al crédito,
  egresos, teléfonos y origen del registro (`voz` o `tecleado`).
- Estados contables coherentes: `PAGADO`, `PARCIAL`, `PENDIENTE` y `ANULADO`.
  El estado se deriva del dinero registrado y no se modifica manualmente.
- Cobros y pagos parciales con historial; cada abono genera su asiento y al
  deshacerlo se elimina también el asiento asociado.
- Edición protegida de órdenes, proformas y cuentas, evitando totales menores
  que lo ya cobrado y evitando inconsistencias entre caja y deudas.
- Arqueo de caja con fondo de apertura, denominaciones y cálculo desde el
  último cierre, sin volver a contar movimientos históricos.
- Corrección de cálculos de vencimientos y exclusión de proformas caducadas de
  los totales vigentes.
- Paginación de las tablas y carga completa por tramos de 1000 registros desde
  Supabase, con límite explícito para no devolver datos incompletos en silencio.
- Exportación real a Excel (`.xlsx`) con hojas de resumen, movimientos,
  órdenes, trabajos, proformas, deudas, abonos y arqueos.
- Tema claro, oscuro y automático según el sistema, incluyendo persistencia
  local y prevención del destello inicial.
- Manejo de errores mediante `ErrorBoundary`, aviso cuando producción funciona
  sin Supabase y eliminación de dependencias de CDN para fuentes e iconos.
- Menú móvil, modales accesibles, confirmaciones de borrado, foco, Escape y
  soporte de impresión de comprobantes.
- Datos de demostración deterministas con volumen suficiente para probar
  paginación, deudas, cierres y exportaciones.
- Dictado por voz con Web Speech API, vocabulario tolerante a transcripciones
  imperfectas, extracción de cifras y validación para no inventar importes,
  nombres o métodos de pago.
- Corpus de evaluación del dictado, pruebas de humo y medición independiente
  de afirmaciones falsas.
- Integración continua en `.github/workflows/ci.yml` para tipos, pruebas de
  humo y build con Node 20.

## Último avance: integración con Claude

En el commit `70053bb` se implementó la segunda fase del dictado: usar Claude
como intérprete inteligente sin exponer la clave en el navegador.

- Se creó la Edge Function `supabase/functions/extraer-dictado`, protegida por
  sesión autenticada y con la clave `ANTHROPIC_API_KEY` únicamente en el entorno
  del servidor.
- Se añadió un prompt especializado para una imprenta peruana, con reglas para
  ingresos, egresos, pedidos, proformas, abonos, deudas, fechas, métodos de
  pago, IGV y frases ambiguas.
- Se definió un JSON Schema versionado y estricto. La respuesta debe tener la
  forma esperada y cualquier dato extra, incompleto o ilegible se rechaza.
- La fecha se calcula en la zona horaria de Lima y se envía en el mensaje, sin
  romper la caché del prompt del modelo.
- El cliente incorpora `extraerCon` y utiliza el modelo solo cuando hay sesión;
  sin sesión o sin Supabase configurado continúa usando las reglas locales.
- Se estableció un timeout de aproximadamente 6 segundos en el cliente y 5
  segundos en la Edge Function. Si Claude falla, tarda, devuelve JSON inválido
  o la red no responde, el formulario vuelve a las reglas y muestra un aviso.
- Se añadió `cruzarConReglas`: si Claude y las reglas encuentran importes
  diferentes, el sistema no adivina; deja el monto vacío y ofrece las opciones
  para que la persona elija.
- Se conserva el origen de la extracción (`llm` o `reglas`) para poder auditar
  cómo se generó cada dictado.
- El evaluador puede medir reglas, Claude o ambos, además de latencia, tokens,
  costo aproximado, fallbacks y modelo que respondió. También permite controlar
  concurrencia, esfuerzo y límite de tiempo.
- Se añadió un segundo corpus de control para comparar el comportamiento fuera
  del corpus usado para ajustar las reglas.
- Se actualizaron dependencias, contrato de tipos y configuración de Supabase;
  el SDK de Anthropic queda fuera del bundle del navegador.

## Verificación realizada

- `npm run smoke` - correcto; todas las comprobaciones pasaron.

El smoke también verificó la nueva integración sin hacer llamadas externas:
respuestas válidas e inválidas, rechazo, JSON cortado, timeout, cancelación de
la solicitud, fallback a reglas, zona horaria de Lima y resolución de conflictos
entre el modelo y las reglas.

No se ejecutó `npm run voz:evaluar -- --motor llm` porque requiere una clave real
`ANTHROPIC_API_KEY` y una Edge Function o acceso de red al modelo. Por tanto, la
latencia, costo real, calidad de Claude y despliegue de Supabase todavía no están
verificados en este entorno.

El build mostró únicamente una advertencia de tamaño para el bundle principal
y para el bloque de ExcelJS. No impidió la compilación.
